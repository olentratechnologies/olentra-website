# Internship email flow

Manage automated emails in **Intern admin → Settings → Templates → Automated emails** (`/intern/dashboard/settings`). The company dashboard email-template section remains retired.

The ten built-in templates are application received, shortlisted, interview scheduled/updated, interview reminder, interview cancelled, selected, formal offer, onboarding approved, certificate issued, and requested sign-in. Admins can edit subjects and plain-text messages, preview sample output, save, or restore defaults. Manual message templates remain available below the automated editor.

Saved overrides live in the internship database's `automated_email_templates` collection, with the configured collection prefix. Defaults remain available without a database migration. The delivery renderer reads the saved copy at send time; preview uses the same renderer. Only internship admins can list, preview, save, or reset automated templates. Supported placeholders are shown per email; unknown placeholders and subject line breaks are rejected.

| Trigger | Email behavior |
| --- | --- |
| Application submitted | Receipt, reference ID, and 3–5 business-day review estimate. No portal or activation link, even if a legacy caller supplies one. |
| Repeat application with the same email | Rejected with `ALREADY_APPLIED`; no new application, confirmation or sign-in email. Email comparison ignores case and surrounding whitespace, across all tracks and statuses. Retrying the same request ID returns its original result without repeating side effects. |
| Status changes to Shortlisted | Shortlist confirmation without a portal link. |
| Interview scheduled or changed | Date/time in IST and UTC, meeting link, portal link, and calendar invite. The calendar UID stays stable and its sequence increases. Portal access still requires selection. |
| Interview within the next 24 hours | Reminder from the hourly worker. Rescheduling resets the reminder; superseded, cancelled, or past interview reminders are skipped at delivery. |
| Interview cancelled | Cancellation email and calendar cancellation with the same UID and a higher sequence. |
| Status changes to Selected | Welcome email, single-use activation link (24 hours), and LinkedIn announcement link. |
| Admin sends an offer | Invitation to review and respond in the portal. |
| Admin approves submitted onboarding | Approval confirmation and portal link. |
| Certificate issued for an eligible completed intern | Verification and LinkedIn sharing links. Existing certificates do not queue another issuance email. |
| Applicant requests sign-in | A single-use link only for explicit Selected/Joined status. Missing status does not grant eligibility. Redemption also checks application eligibility. |

Required links, reference details, security notices and calendar attachments are generated by the system. Editable receipt and shortlist copy cannot include URLs. HTML in editable copy is escaped. Rejection emails retain the existing opt-in setting.

Workflow email jobs are inserted in the same transaction as their state changes. Idempotent command replay does not enqueue a second job. Provider failures retry with the existing outbox backoff. As with any external email provider, a successful send followed by a lost acknowledgement can still result in a duplicate delivery.

Commands: `automatedEmail.list`, `automatedEmail.preview`, `automatedEmail.save`, and `automatedEmail.reset`. Save/preview take `{ id, subject, body }`; reset takes `{ id }`. Preview never sends an email or generates a real activation token.

Run backend checks from the repository root with `npm run realtime:typecheck` and `npm run realtime:test`. MongoDB integration tests require an explicitly isolated `INTERNSHIP_TEST_MONGODB_URI`; they never fall back to the runtime database.

## Central email delivery

Only email-server connects to Google SMTP. Realtime renders saved templates, generates
secure URLs and queues workflow jobs, then calls authenticated `POST /api/email`.
Contact enquiries use the same SMTP sender through the existing `/api/contact` route.
SMTP acceptance is required before reporting delivery success. Missing credentials
and central-service failures are failures in development and production alike.

For localhost, set `EMAIL_SERVER_URL=http://127.0.0.1:3001` in realtime-server. Live
realtime points to its deployed email-server (loopback if co-hosted, HTTPS otherwise).
Set the same `EMAIL_DELIVERY_TOKEN` on the paired services. SMTP credentials belong
only in email-server's environment; see its README. Update every worker using the
shared database before relying on the new templates and sender.
